# 시스템 구조

[English](system_overview.en.md)

수업에서 만드는 군집 비행 시스템의 전체 모양과, 부품끼리 주고받는 약속이다.

```
[천장 카메라 mocap] --위치--> [지상국] --목표 위치--> [무선 link] --> [드론 6대의 칩]
 시뮬: 가상 카메라             부원이 짠 군집 알고리즘   시뮬: localhost UDP      시뮬: 엔진 + 부원의 다단 PID
 실제: ArUco 천장 카메라        (대형, 합의, 회피)        실제: ESP32 Wi-Fi UDP    실제: 펌웨어
```

지상국 코드는 시뮬레이션과 실기체에서 똑같다. 실기체로 갈 때 바뀌는 것은 `mocap`(ArUco 노드로), `link`(`EspUdpLink`로), 그리고 시뮬레이션에만 있는 `sim_bridge`뿐이다.

### 인터페이스 약속

- 좌표계: world ENU, 단위는 m, s, rad. 드론 이름은 `cf1`~`cf6`.
- 상태: `pose = {id, t, p:[x,y,z], q:[w,x,y,z]}`. 카메라는 위치만 주고, 속도는 지상국에서 차분해서 구한다.
- 명령: `takeoff(h, dur)`, `go_to(p, yaw, dur)`, `cmd_position(p, yaw)`(50 Hz 스트림), `land(dur)`, `emergency_stop()`. Crazyflie와 같은 이름을 쓴다.
- ROS 2 토픽: `/cfN/pose`(PoseStamped, 100 Hz), `/cfN/setpoint`(PoseStamped, 50 Hz), `/cfN/command`(String JSON), `/swarm/formation`(String JSON), `/swarm/emergency`(Empty), `/swarm/status`(String JSON).
- ROS 2는 노트북 안에서만 쓴다. 드론과는 UDP로만 통신하고 DDS를 Wi-Fi 너머로 보내지 않는다.

물리 엔진은 Crazyflow 0.4.0(JAX 물리, MuJoCo 렌더)으로 정했다. 다른 엔진과 비교한 결과는 [`docs/engine_bakeoff.md`](engine_bakeoff.md)에 있다. 기체 모델은 `cf2x_T350`(37.9 g)이다.
